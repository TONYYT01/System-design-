# C# Fundamentals: Core Program Structure & Keywords

A complete guide to the foundational building blocks of a C# console application: `using System;`, `class Program`, `Main()`, and the `static` keyword.

---

## 1. `using System;`

In C#, `using System;` is a **directive** that imports the core `System` namespace, allowing you to use its classes and types directly without typing out fully qualified names.

### Purpose and Usage

Without `using System;`, every core type requires its full path:

```csharp
System.Console.WriteLine("Hello, World!");
System.DateTime now = System.DateTime.Now;
System.Math.Sqrt(16);
```

With `using System;` declared at the top of the file:

```csharp
using System;

Console.WriteLine("Hello, World!");
DateTime now = DateTime.Now;
Math.Sqrt(16);
```

### What `System` Contains

* **Primitive types:** `int` (`System.Int32`), `string` (`System.String`), `bool` (`System.Boolean`), `double`, etc.
* **Console operations:** `Console.ReadLine()`, `Console.WriteLine()`
* **Math & Time:** `Math`, `DateTime`, `TimeSpan`
* **Base exceptions:** `Exception`, `ArgumentNullException`, `InvalidOperationException`

### Modern C# (Implicit Usings)

In **.NET 6+ (C# 10+)**, standard templates enable implicit imports via the project file (`.csproj`):

```xml
<PropertyGroup>
    <ImplicitUsings>enable</ImplicitUsings>
</PropertyGroup>
```

When enabled, the compiler imports common namespaces (`System`, `System.Collections.Generic`, `System.Linq`, etc.) behind the scenes, making manual `using System;` lines optional in console apps.

## 2. `class Program`

`class Program` is the standard container class hosting the entry point (`Main`) of a C# application.

### Classic Structure

```csharp
using System;

namespace MyFirstApp
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("Hello, World!");
        }
    }
}
```

* **`class Program`**: C# enforces an object-oriented structure; all executable functions must belong to a type (class, struct, or record). By convention, the primary class is named `Program`.
* **Naming Flexibility**: The class name does **not** have to be `Program`. The .NET runtime scans for the entry method named `Main`, regardless of which class wraps it:

```csharp
class Runner
{
    static void Main()
    {
        Console.WriteLine("Executes successfully.");
    }
}
```

### Modern Top-Level Statements

Starting in **C# 9**, top-level statements allow omitting namespace and class boilerplate:

```csharp
Console.WriteLine("Hello, World!");
```

During compilation, the compiler automatically generates `class Program` and `static void Main(string[] args)` around your code.

---

## 3. `static void Main()`

`Main` is the **application entry point**. The Common Language Runtime (CLR) invokes this method first when executing an application.

### Syntax Breakdown

```csharp
static void Main(string[] args)
```

| Element | Description |
|---|---|
| `static` | Allows the CLR to execute the method directly on the class without instantiating an object first (`new Program()`). |
| `void` | Specifies that the method returns no status code upon process termination. |
| `Main` | Must begin with an uppercase `M`. Lowercase `main` compiles as a standard method but is not recognized as the entry point. |
| `string[] args` | Array holding CLI arguments supplied when launching the executable. |

### Valid Signatures

Depending on argument handling, exit status reporting, or asynchronous tasks, `Main` accepts these variations:

```csharp
// Standard entry points
static void Main() { }
static void Main(string[] args) { }

// Return integer exit codes (0 = success, non-zero = error)
static int Main() { return 0; }
static int Main(string[] args) { return 0; }

// Asynchronous entry points
static async Task Main() { await Task.Delay(100); }
static async Task<int> Main(string[] args) { return await Task.FromResult(0); }
```

## 4. The `static` Keyword

In C#, `static` means **associated with the class itself rather than an instance of the class**.

### Instance vs. Static Memory

* **Instance Member:** Exists separately in each object created via `new`.
* **Static Member:** Exactly **one copy** exists in memory, shared across the entire application runtime. Accessed via `ClassName.MemberName`.

```csharp
class Counter
{
    public int instanceCount = 0;      // Unique per object
    public static int globalCount = 0; // Shared across all instances
}

class Program
{
    static void Main()
    {
        Counter a = new Counter();
        Counter b = new Counter();

        a.instanceCount++;
        b.instanceCount++;

        Counter.globalCount++;
        Counter.globalCount++;

        Console.WriteLine(a.instanceCount);     // Output: 1
        Console.WriteLine(b.instanceCount);     // Output: 1
        Console.WriteLine(Counter.globalCount); // Output: 2 (Shared)
    }
}
```

### Key Applications of `static`

1. **Static Methods:** Utility routines that operate solely on input arguments without reading or modifying object instance state:
   ```csharp
   public static class MathHelper
   {
       public static int Add(int a, int b) => a + b;
   }
   ```
2. **Static Classes:** Classes defined with `static` cannot be instantiated via `new` and can contain only static members (e.g., `System.Math`, `System.Console`).
3. **Static Constructors:** Parameterless constructors that execute **once** before the class is first accessed in memory:
   ```csharp
   class CacheManager
   {
       static CacheManager()
       {
           // Initialization code executed once
       }
   }
   ```

### Core Constraints

* Inside a `static` method, accessing `this` or instance-level fields directly is prohibited because no specific object instance exists in that context.
* Instance methods can freely read and modify static fields.


```csharp
    using System;

    namespace Learn
    {
        class program
        {
            static void Main(string[] args)
            {
                Console.WriteLine("Hello");
                Console.ReadKey();
            }
        }
    }
```
