# DAY 10 — 10%
## C# Methods Advanced + Method Overloading

Building directly on Day 9's foundation, today covers **Method Overloading**, an essential feature of C# methods and compile-time polymorphism.

The core goal of this 1% is to understand **how C# distinguishes between multiple methods sharing the same identifier, and what constitutes a valid method signature**.

---

### 1️⃣ What is Method Overloading?

**Method overloading** allows a class to define multiple methods with the **exact same name**, provided each method has a **different parameter list**.

```csharp
class Calculator
{
    public int Add(int a, int b)
    {
        return a + b;
    }

    public int Add(int a, int b, int c)
    {
        return a + b + c;
    }
}
```

Both methods are named `Add`, but their signatures differ:
* `Add(int, int)`
* `Add(int, int, int)`

C# resolves which method to invoke at compile time based on the arguments supplied:

```csharp
Calculator c = new Calculator();
Console.WriteLine(c.Add(10, 20));       // Output: 30
Console.WriteLine(c.Add(10, 20, 30));   // Output: 60
```

---

### 2️⃣ How C# Identifies an Overloaded Method

The compiler evaluates the **method signature**, specifically:
1. The **number** of parameters
2. The **types** of parameters
3. The **order** of different parameter types

#### Valid Overload Patterns:

```csharp
// 1. Different parameter types
void Print(int x) { }
void Print(string x) { }

// 2. Different number of parameters
void Print(int x) { }
void Print(int x, int y) { }

// 3. Different order of parameter types
void Print(int x, double y) { }
void Print(double x, int y) { }
```

---

### 3️⃣ ❌ Return Type Alone Cannot Overload

> **Core Rule:** Method overloading **cannot** be achieved solely by altering the return type.

#### ❌ Invalid Example:

```csharp
int Add(int a, int b)
{
    return a + b;
}

double Add(int a, int b) // ❌ Compile Error: Type already defines a member called 'Add' with the same parameter types
{
    return a + b;
}
```

#### Why?
When a method is called without assigning its result (e.g., `Add(5, 10);`), the compiler cannot determine which method was intended. The parameter list is identical: `(int, int)`.

### 4️⃣ Real-World Example: Order Processing

Consider calculating checkout totals where pricing factors vary by transaction:

```csharp
class OrderService
{
    public double CalculateTotal(double price)
    {
        return price;
    }

    public double CalculateTotal(double price, double tax)
    {
        return price + tax;
    }

    public double CalculateTotal(double price, double tax, double shipping)
    {
        return price + tax + shipping;
    }
}
```

Usage:

```csharp
OrderService service = new OrderService();

Console.WriteLine(service.CalculateTotal(100));            // Base price: 100
Console.WriteLine(service.CalculateTotal(100, 18));        // Price + Tax: 118
Console.WriteLine(service.CalculateTotal(100, 18, 50));    // Price + Tax + Shipping: 168
```

*One clear operation (`CalculateTotal`) cleanly handles varying tiers of input data.*

---

### 5️⃣ Overloading vs. Redundant Naming

#### Without Overloading (Cluttered API):
```csharp
AddTwoNumbers(int a, int b)
AddThreeNumbers(int a, int b, int c)
AddFourNumbers(int a, int b, int c, int d)
```

#### With Overloading (Clean & Expressive):
```csharp
Add(int a, int b)
Add(int a, int b, int c)
Add(int a, int b, int c, int d)
```

The method name represents the **semantic action**, while the parameter list directs execution to the correct implementation.

---

### 6️⃣ Parameters vs. Arguments (Quick Review)

* **Parameter:** The variable declared in the method definition.
  ```csharp
  int Add(int a, int b) // 'a' and 'b' are parameters
  ```
* **Argument:** The concrete value supplied during invocation.
  ```csharp
  Add(10, 20); // '10' and '20' are arguments
  ```

### 7️⃣ Overloading Across Different Data Types

```csharp
class Printer
{
    public void Print(int number)
    {
        Console.WriteLine($"Integer: {number}");
    }

    public void Print(string text)
    {
        Console.WriteLine($"String: {text}");
    }

    public void Print(double number)
    {
        Console.WriteLine($"Double: {number}");
    }
}
```

Usage:

```csharp
Printer p = new Printer();
p.Print(10);        // Resolves to Print(int)
p.Print("Hello");   // Resolves to Print(string)
p.Print(10.5);      // Resolves to Print(double)
```

---

### 8️⃣ Overloading with Different Return Types

Methods **can** return different types, provided their parameter lists also differ:

```csharp
int Calculate(int a, int b)
{
    return a + b;
}

double Calculate(double a, double b)
{
    return a + b;
}
```

> **Note:** This is valid because `(int, int)` and `(double, double)` are distinct parameter signatures, not because of the differing return types.

---

### 9️⃣ Constructor Overloading Preview

Constructors follow the exact same overloading mechanics:

```csharp
class User
{
    public User() { }
    public User(string name) { }
    public User(string name, int age) { }
}
```

*Same constructor identifier (`User`), different initialization parameters.*

### 🔟 Backend Scenario: Query Operations

In Web APIs and repository architectures, overloading provides multiple lookup strategies for an entity:

```csharp
GetUser(int id)
GetUser(string email)
```

Execution dispatch:
```
GetUser(101)                ──> Executes GetUser(int id)
GetUser("dev@company.com")   ──> Executes GetUser(string email)
```

### 🧠 Interview Checkpoint

Make sure you can answer these without reference:

#### Q1. What is method overloading?
Defining multiple methods within the same class that share the same name but have distinct parameter lists (signatures).

#### Q2. Can methods be overloaded solely by changing the return type?
**No.** The compiler requires differences in parameter count, types, or ordering.

#### Q3. What parameters qualify an overload as valid?
* Different number of parameters
* Different types of parameters
* Different sequence/order of parameter types

#### Q4. Is this valid?
```csharp
void Test(int x) { }
int Test(int x) { return x; }
```
**Answer:** ❌ **Invalid.** The parameter signatures `(int)` are identical.

#### Q5. Is this valid?
```csharp
void Test(int x) { }
void Test(string x) { }
```
**Answer:** ✅ **Valid.** The parameter types differ (`int` vs. `string`).
