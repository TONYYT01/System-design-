# DAY 7 — 7%
## C# `while` + `do-while` Loops

Today continues **C# Control Flow**. Following the `for` loop in Day 6, today focuses on **condition-driven repetition**: understanding when a `while` loop is more natural than a `for` loop, and the critical distinction between entry-controlled (`while`) and exit-controlled (`do-while`) execution.

---

### 1️⃣ The `while` Loop (Entry-Controlled)

The `while` loop checks its condition **before** executing the loop body.

```csharp
while (condition)
{
    // loop body
}
```

#### Example:

```csharp
int i = 1;

while (i <= 5)
{
    Console.WriteLine(i);
    i++;
}
```

#### Step-by-Step Lifecycle:
```
i = 1
  ↓
Check: 1 <= 5? (True)
  ↓
Execute body: Prints 1
  ↓
Increment: i becomes 2
  ↓
Check: 2 <= 5? (True)
  ↓
... repeats ...
  ↓
Check: 6 <= 5? (False)
  ↓
Terminate loop
```

> **Core Rule:** In a standard `while` loop, if the condition is `false` from the start, the loop body **never** executes.

---

### 2️⃣ What Happens When the Initial Condition is `false`?

```csharp
int i = 10;

while (i <= 5)
{
    Console.WriteLine(i);
    i++;
}
```

**Output:** *Nothing prints.*

Because `10 <= 5` evaluates to `false` on the initial check, the entire block is bypassed immediately.

---

### 3️⃣ The `do-while` Loop (Exit-Controlled)

The `do-while` loop executes its body first, and **then** tests the condition at the end of the iteration.

```csharp
do
{
    // loop body
} while (condition);
```

#### Example:

```csharp
int i = 1;

do
{
    Console.WriteLine(i);
    i++;
} while (i <= 5);
```

**Output:**
```text
1
2
3
4
5
```

> **Key Rule:** A `do-while` loop **always executes at least once**, regardless of whether the condition is true or false initially.

---

### 4️⃣ `while` vs. `do-while` Comparison

Consider what happens when the starting value violates the condition:

#### `while` (Pre-Test)
```csharp
int i = 10;

while (i <= 5)
{
    Console.WriteLine(i);
}
```
**Output:** *(None)*

#### `do-while` (Post-Test)
```csharp
int i = 10;

do
{
    Console.WriteLine(i);
} while (i <= 5);
```
**Output:** `10`

#### Execution Summary:
* **`while`**: `Condition Check` $\rightarrow$ `Execute Body`
* **`do-while`**: `Execute Body` $\rightarrow$ `Condition Check`

---

### 5️⃣ When to Choose `while` Over `for`

* **Use `for`** when the **number of iterations is known** in advance (e.g., arrays, fixed ranges $1 \dots N$).
* **Use `while`** when looping is based on a **dynamic state or condition**, where you do not know beforehand how many iterations will be required.

#### Example: State-Driven Looping

```csharp
int number = 1;

while (number < 100)
{
    Console.WriteLine(number);
    number *= 2;
}
```

Output:
```text
1
2
4
8
16
32
64
```
Here, execution continues as long as `number < 100`, rather than running a predetermined number of times.

---

### 6️⃣ Backend Scenario: Interactive Polling & Menus

A common pattern for interactive prompts, polling workers, or retries:

```csharp
int option = 0;

while (option != 3)
{
    Console.WriteLine("1. Add");
    Console.WriteLine("2. View");
    Console.WriteLine("3. Exit");

    // Simulated user input / exit trigger
    option = 3; 
}
```

The process repeats indefinitely until an external termination state is reached.

---

### 7️⃣ ⚠️ The Danger of Infinite Loops

A loop becomes infinite when its termination condition never evaluates to `false`:

```csharp
int i = 1;

// ❌ Bug: i is never incremented, so (1 <= 5) remains true forever
while (i <= 5)
{
    Console.WriteLine(i);
}
```

To prevent runaway CPU consumption and application hangs, ensure the loop body modifies state toward the exit condition:

```csharp
i++; // ✅ Moves state closer to (i <= 5) becoming false
```

### 8️⃣ Combining Loops with Prior Concepts

Loops frequently combine with arithmetic operators and conditional branching:

```csharp
int i = 1;

while (i <= 10)
{
    if (i % 2 == 0)
    {
        Console.WriteLine(i);
    }
    i++;
}
```
